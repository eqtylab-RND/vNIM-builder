The new seven deterministic CPU tests cover aligned/disjoint packing with
large offsets, per-call fresh runner invocation, refusal to substitute spans,
source-hash gating, bounded/waited async copies, no release ACK on protocol
failure, retention of the cleanup ledger after a failed close, and preserving
outliers while excluding profiler timings from performance aggregates.

The 181-case device probe covers 45 lengths at offsets 0, 1, 7 and 16,
including 64-byte compression boundaries, 1-KiB BLAKE3 chunks, 128-KiB tiles,
multiple tiles and randomized partial lengths. A mixed-span call also checks
every tensor digest and the count-prefixed model fold. Reference hashes come
from Python's trusted `blake3` package, not another copy of the CUDA template.
Existing cryptographic tests additionally upload/read back 4,096 identical
1-KiB blocks, compare BLAKE3/SHA-256/HMAC, and exercise P-256 arithmetic and
signatures against independent Python/library oracles.

## Compute Sanitizer

All **eight** invocations passed on Blackwell GPU 0 using the asynchronous
candidate and the full 181-case probe. Both exit codes and diagnostic text
were inspected, not merely the Python process's success code.

| Tool | Native C++ host | Python fallback |
| --- | --- | --- |
| memcheck | 0 errors; 0 leaked bytes/allocations | 0 errors; 0 leaked bytes/allocations |
| initcheck, global + shared | 0 errors | 0 errors |
| racecheck, informational hazards enabled | 0 hazards/errors/warnings | 0 hazards/errors/warnings |
| synccheck | 0 errors | 0 errors |

Enabled options include strict driver API reporting, full leak checking,
32-byte allocation padding, module-unload checking, stream-ordered races,
bulk-copy and tensor-operation checks, and informational race hazards. These
are direct-driver probe runs, not IPC global-initcheck runs: Compute Sanitizer
does not track initialization across producer/consumer IPC boundaries.

In particular, the new lane-owned `cp.async` staging path is exercised by full
aligned pairs while neighboring tail/unaligned lanes exercise the unchanged
general path. Completion is explicitly waited before shared reads/reuse; no
block-wide barrier is introduced into divergent lane control flow. Test
timings under instrumentation are not pooled with latency results.

## Limits and disposition

- The full-tile specialization passed correctness checks but lost performance;
  it remains an archived candidate, not a default. The single-buffer control
  also lost to double buffering.
- Registration is a bounded, owned-process, single-client prototype. The
  producer holds leases across responses, unknown completion stays quarantined,
  and any server error is fatal without a release ACK. This is not a substitute
  for comprehensive public-API disconnect/concurrency/producer-event review.
- Packed storage is audited by its experimental loader; the existing strict
  capacity auditor was not weakened to accept arbitrary aliases or padding.
- On the local RTX 2080, the full-tile candidate compiled and passed the
  181-case differential probe. Subsequent baseline/model checks failed before
  CUDA initialization with error 803 / NVML driver-library mismatch: loaded
  kernel module **610.43.02**, installed userspace **610.57.04**. No driver
  changes or reboot were performed. No local comparative speedup is claimed,
  and async performance on other architectures remains unqualified.
- Host C++ did not change, so this campaign did not rerun ASan/UBSan/TSan/MSan;
  the [earlier host sanitizer audit](sanitizers-2026-09-08.md) remains separate.
- Both full-model producer phases and their owned servers were stopped. Their
  VRAM was released; no unrelated processes were terminated or GPU clocks
  changed.
